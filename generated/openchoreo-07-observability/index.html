部署完成不代表運作正常。這一課啟用 Observability Plane,讓平台自動收集你應用的日誌、指標與 Kubernetes 事件。

  • 已完成第 1 到 3 課
  • 資源:建議 8 GB RAM 以上,主機磁碟至少 10 GB 可用(OpenSearch 與 Prometheus 會佔用)
  • 能連到 ghcr.io(需要下載多個 Helm chart 與映像)

你會學到

  • 日誌、指標、事件各自存放在哪裡
  • 如何用 kubectl port-forward 直接查底層資料來排錯
  • 追蹤(Tracing)需要什麼條件(實際驗證在第 9 課)

Negative : 本課的 Observer API、occ component logs 與入口網站的觀測畫面都需要 OAuth 登入,作者在自動化環境無法完成瀏覽器登入,所以這些介面沒有實際操作,只有列出指令。底層的 OpenSearch 與 Prometheus 查詢則是實測過的。

「為什麼出問題?我沒預料到的問題呢?」

做法

系統一複雜(尤其是微服務),你無法預先猜到所有問題,所以需要能「事後提問」的資料。

三大支柱 + 事件

支柱

它是什麼

回答的問題

例子

日誌(Logs)

帶時間戳的文字紀錄

「發生了什麼事?」

Starting HTTP Greeter on port 9090

指標(Metrics)

隨時間變化的數字

「整體狀況如何?趨勢?」

CPU 使用率、每秒請求數

追蹤(Traces)

一個請求經過各服務的完整路徑

「這個請求慢在哪裡?」

frontend → checkout → payment

事件(Events)

Kubernetes 的狀態變化紀錄

「叢集做了什麼?」

Pod 被排程、映像拉取失敗

三者互補:指標告訴你有問題,追蹤告訴你問題在哪個服務,日誌告訴你為什麼。

追蹤的詞彙

名詞

說明

Trace(追蹤)

一個請求從頭到尾的完整紀錄,有唯一的 traceId

Span(跨度)

追蹤中的一個步驟(例如「呼叫 payment 服務」),有起訖時間、spanId、parentSpanId

傳遞(propagation)

服務之間透過標頭傳遞 traceId,才能把各服務的 span 串成一棵樹

因為追蹤需要程式碼配合(埋點),所以不像日誌那樣「自動就有」。這也是為什麼第 3 課的 Greeter 沒有追蹤資料。

OpenTelemetry

OpenTelemetry(OTel) 是 CNCF 的觀測資料標準與工具集,核心是統一「資料長什麼樣、怎麼傳」:

元件

說明

SDK

放進你的應用程式,產生 span、指標

OTLP

傳輸協定(gRPC 4317 或 HTTP 4318)

Collector

接收、處理(例如附加 Kubernetes 標籤)、轉送到後端

好處是與廠商無關:今天送到 OpenSearch,明天換別的後端,應用程式不用改。

各元件在做什麼?

元件

做法

Fluent Bit

以 DaemonSet 在每個節點跑一份,讀取容器的 stdout/stderr 日誌檔,轉送出去

Prometheus

以**拉取(pull)**方式,定期去各目標的 /metrics 端點抓數字,存成時間序列;用 PromQL 查詢

OpenSearch

可水平擴充的搜尋引擎,擅長全文檢索,適合存日誌與追蹤

kube-state-metrics

把 Kubernetes 物件的狀態(例如 Pod 重啟次數)轉成指標

為什麼標籤(labels)這麼重要?

原始的容器日誌只知道「來自某個 Pod」。OpenChoreo 的收集管線會附上 component、project、environment 等標籤。這讓你能問平台層級的問題:「development 環境裡 checkout 元件的錯誤日誌」,而不是去猜 Pod 名稱(Pod 名稱每次重建都會變)。

為什麼觀測資料要放在獨立的 Plane?

  • 觀測資料量大,不該和業務服務搶資源
  • 服務掛了,觀測系統必須還活著,才能告訴你為什麼掛
  • 可以集中收集多個 Data Plane 的資料

可替換的模組化設計

OpenChoreo 把日誌、指標、追蹤各做成獨立的 Helm 模組,透過 adapter(轉接器) 對外提供統一的查詢介面。想換掉 OpenSearch 或 Prometheus,只要換對應的模組即可。

下面就來安裝它們。

元件

角色

Fluent Bit

DaemonSet,收集每個節點上容器的日誌

OpenSearch

儲存日誌、事件(與追蹤)

Prometheus + kube-state-metrics

收集指標

OpenTelemetry Collector

接收 OTLP 追蹤(gRPC 4317 / HTTP 4318)

events-collector

把 Kubernetes 事件寫進 OpenSearch

logs / metrics / tracing adapter

把各後端包成統一的查詢介面

Observer

對外的查詢 API,需要 OAuth token

cluster-agent

與控制平面通訊

資料流向:

容器 stdout ─▶ Fluent Bit ─▶ OpenSearch ─▶ logs-adapter ┐
cAdvisor/kube-state ─▶ Prometheus ─▶ metrics-adapter    ├─▶ Observer ─▶ Backstage / occ / MCP
應用 OTLP ─▶ OTel Collector ─▶ OpenSearch ─▶ tracing-adapter ┘

Positive : OpenChoreo 的觀測是可替換的模組:日誌、追蹤、指標各自是一個 Helm 模組,平台團隊可以換成其他後端,只要實作對應的 adapter。

1. Namespace 與 CA

2. 密鑰(OpenSearch 帳密與 Observer OAuth)

kubectl apply -f - <<EOF
apiVersion: external-secrets.io/v1
kind: ExternalSecret
metadata:
  name: opensearch-admin-credentials
  namespace: openchoreo-observability-plane
spec:
  refreshInterval: 1h
  secretStoreRef:
    kind: ClusterSecretStore
    name: default
  target:
    name: opensearch-admin-credentials
  data:
  - secretKey: username
    remoteRef: {key: opensearch-username, property: value}
  - secretKey: password
    remoteRef: {key: opensearch-password, property: value}
---
apiVersion: external-secrets.io/v1
kind: ExternalSecret
metadata:
  name: observer-secret
  namespace: openchoreo-observability-plane
spec:
  refreshInterval: 1h
  secretStoreRef:
    kind: ClusterSecretStore
    name: default
  target:
    name: observer-secret
  data:
  - secretKey: UID_RESOLVER_OAUTH_CLIENT_SECRET
    remoteRef: {key: observer-oauth-client-secret, property: value}
EOF
kubectl wait -n openchoreo-observability-plane \
  --for=condition=Ready externalsecret/opensearch-admin-credentials externalsecret/observer-secret --timeout=60s

追蹤

OpenTelemetry Collector 在叢集內開放 OTLP 端點:

協定

位址

gRPC

HTTP

opentelemetry-collector.openchoreo-observability-plane:4318

你的應用要自己用 OpenTelemetry SDK 送出 span 到上面的位址。Greeter 範例沒有埋點,所以不會產生任何追蹤。

Positive : 追蹤管線已用真實服務驗證:在第 9 課讓叢集內的微服務把 span 送到上面的 Collector 位址,OpenSearch 出現了 otel-traces-YYYY-MM-DD 索引,span 帶有 K8s 屬性。

Negative : 作者一開始從本機 kubectl port-forward 用 telemetrygen 送測試 span,沒有看到追蹤索引,Collector 也沒有錯誤,原因未查明(推測與 Collector 依來源 Pod 關聯 K8s 屬性有關,未驗證)。要驗證追蹤,請讓叢集內有 OTel 埋點的應用送出 span,做法見第 9 課。

Observer 透過閘道對外:

curl http://observer.openchoreo.localhost:11080/health

回 200。其他端點需要 OAuth token,沒有 token 會被拒絕:

curl -X POST http://observer.openchoreo.localhost:11080/api/v1/logs/query
# {"error":"MISSING_TOKEN","message":"missing or invalid authentication token"}

Observer 只服務已通過身分驗證的使用者(入口網站、occ、MCP server)。
